# Backlog課題起票フロー

ユーザーの依頼と会話コンテキストからBacklog課題の起票案を組み立て、
明示的な承認を得た後に起票する。

このreferenceはBacklog課題の**新規作成**に適用する。既存課題の更新・削除は対象外。
説明とやり取りはすべて日本語で行う。

## 前提

- 対象スペースは`dev-ml`。
- Backlogへ接続できない場合は、起票可能なふりをせず、起票案の作成まで行う。
- 利用可能なBacklogツールを実行時に確認する。ここに記載した操作名と実際のツール名が
  異なる場合は、同等の読み取り・起票機能を使う。
- プロジェクト、種別、件名、優先度は課題作成時の必須項目として扱う。
- プロジェクトに必須カスタムフィールドが設定されている場合は、それらも必須項目として扱う。

## 承認境界

- プロジェクト情報の読み取り、選択肢の取得、会話の要約、起票案の作成は自律実行してよい。
- 実際の課題作成は、完成した起票案を提示し、ユーザーから明示的な承認を得た後に行う。
- 「案を作って」「検討して」などの依頼や、案への「よさそう」という反応を起票承認とみなさない。

## 実行手順

### 1. 依頼と会話から候補を作る

次の項目について、ユーザーの依頼、直近の会話、既知のプロジェクト情報から候補を作る。

- プロジェクト
- 種別
- 件名
- 説明
- 優先度
- カテゴリ
- 担当者
- 期限
- 親課題、マイルストーン、発生バージョン
- カスタムフィールド

ユーザーが明示した値は勝手に置き換えない。推定した値は確定情報と区別する。

### 2. Backlogから必要情報をまとめて取得する

利用可能な読み取り機能を使い、必要な範囲で次を取得する。

- ログインユーザー
- プロジェクト一覧と対象プロジェクト
- 対象プロジェクトの種別
- 優先度
- カテゴリ
- プロジェクトメンバー
- マイルストーン・バージョン
- カスタムフィールドと必須条件

依頼から対象プロジェクトを一意に特定できる場合、プロジェクト一覧を毎回ユーザーへ
提示する必要はない。不要な一覧取得や長大な選択肢の提示を避ける。

### 3. 不足している重要項目だけ確認する

取得した情報と会話コンテキストを突き合わせ、次に該当する項目だけをまとめて質問する。

- 必須だが安全に推定できない項目
- 候補が複数あり、選択によって結果が大きく変わる項目
- 担当者、期限、公開情報など、誤った推定の影響が大きい項目

確認時は推奨案を先に示し、番号付きリストで回答できるようにする。
任意項目には「設定しない」を用意する。ユーザーが「おまかせ」と指定した項目は、
妥当な既定値を選び、最終確認時にその値を明示する。

優先度は必須のため、省略しない。指定がなければ優先度一覧を取得し、通常運用に適した
値を推奨案として提示する。

### 4. 件名と説明を組み立てる

件名は、対象と行動が分かる簡潔な表現にする。説明は課題の性質に応じて調整するが、
既定では次の構成を使う。

```text
## 概要
（課題の目的を1〜2文で記載）

## 背景
（会話や調査から分かった背景を要約）

## 対応内容
- [ ] （具体的なアクション）

## 完了条件
- [ ] （何をもって完了とするか）

## 補足
（制約、参考情報、未確認事項など）
```

- 会話に存在しない事実、決定、期限、担当者を創作しない。
- 未確認事項は断定せず、「要確認」またはプレースホルダーとして示す。
- 社内文書の生テキストを必要以上に転載せず、課題の遂行に必要な内容へ要約する。
- プロジェクトの課題テンプレートが取得できる場合は、そのテンプレートを優先する。

### 5. 起票前の最終確認

実際の起票直前に、次のうち設定する項目を一度にまとめて提示する。

- プロジェクト
- 種別
- 件名
- 説明全文
- 優先度
- カテゴリ
- 担当者
- 期限
- 親課題、マイルストーン、発生バージョン
- カスタムフィールド

推定値と未確認事項があれば併記し、「この内容で起票してよいか」を明示的に確認する。
修正依頼を受けた場合は案を更新し、更新後の内容について改めて承認を得る。

### 6. 起票と結果報告

承認された内容だけを使って課題を作成する。

起票後は、次を確認して報告する。

- 課題キー
- 件名
- URL
- 担当者と期限
- 起票時に反映できなかった項目や警告

作成に失敗した場合は、成功したように報告しない。エラーの要点、再試行の可否、
保持している起票案を報告する。

## 例外

- ユーザーがプロジェクトを特定できない場合は、候補を絞って提示する。
- 必須カスタムフィールドの値が不明な場合は、起票せずに確認する。
- 対象プロジェクトへの権限がない場合は、起票案を提示して権限不足を報告する。
- 既存課題と重複する可能性が高い場合は、起票前に類似課題を確認し、重複候補を提示する。
