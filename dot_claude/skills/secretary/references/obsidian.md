# Obsidian Exocortex連携

secretaryが受けた依頼を、ユーザーの第二の脳であるExocortexの適切な操作へ
橋渡しするためのreference。

このファイルは**ルーター兼ブリッジ**であり、Vaultの構造、frontmatter、
保存規約、具体的な操作手順を定義しない。それらの唯一の正は、作業時点の
`~/Workspace/exocortex/CLAUDE.md`とする。

## 対象

- クイックメモ
- ソースや会話内容の取り込み
- Wikiへの問い合わせ
- Wikiの健全性チェック
- 個人タスクの追加・更新・完了・棚卸し
- 知識と個人タスクをまたぐ操作

## 作業前の必須確認

1. `~/Workspace/exocortex/CLAUDE.md`を最初から最後まで読む。
2. 必要に応じてVaultの`README.md`と、依頼に関係する既存ページを読む。
3. 依頼をVault側で定義された操作へ分類する。
4. 保存先、ファイル名、frontmatter、リンク、index・log更新、承認要否を
   Vault側の最新規約から確認する。

Vault側の規約とこのreferenceの記述が食い違う場合は、Vault側の`CLAUDE.md`を優先する。
Workspaceの`CLAUDE.md`やsecretaryの`SKILL.md`に、より厳しい承認ルールがある場合は
そのルールにも従う。

## ルーティング

依頼を、Vault側の`CLAUDE.md`で定義されている操作へ振り分ける。
現在想定する代表的な分類は次のとおりだが、名称や手順は必ずVault側で再確認する。

| 依頼の例 | 代表的な操作 |
|---|---|
| 「メモして」「後で整理する」 | クイックキャプチャ |
| 「取り込んで」「Wikiに要約して」 | 知識の取り込み |
| 「Wikiから教えて」「比較して」 | 問い合わせ |
| 「Wikiを点検して」 | 健全性チェック |
| 「タスク追加」「完了にして」「今日のタスク」 | 個人タスク操作 |

- 複数の操作にまたがる場合は、Vault側の設計に従って依存順に実行する。
- 分類が曖昧でも安全に読み取り・整理できる範囲は先に進める。
- 保存先や既存ページへの影響が大きく変わる場合だけ、ユーザーへ確認する。

## secretary固有の役割

- ユーザーの自然言語の依頼を、適切なExocortex操作へ変換する。
- 会話コンテキストを整理し、ユーザーの再入力を減らす。
- Backlog、Notion、research、marketing、pmとの境界を調整する。
- 実行結果、作成・更新したファイル、未確認事項、次アクションをまとめて報告する。

## 境界

- `raw/`は読み取り専用とする。ユーザーがstaffによる例外操作を明示した場合だけ、
  Vault側の承認手順に従う。
- 長期的に再利用する知識と、実行すべき行動を混在させない。
- 個人タスクはExocortex、プロジェクト課題はBacklog、
  チームドキュメントはNotionを正とする。
- 確定的な会社データをExocortexへ二重管理しない。
- 会社関連の知見を記録する場合は、Vault側の匿名化ルールに従う。
- Obsidianアプリの画面操作ではなく、Vault内のファイルを操作する。

## 承認と実行

- 読み取り、検索、問い合わせ、下書き作成は自律実行してよい。
- ファイルの作成・更新、タスク化、index・log・相互リンクの保守については、
  WorkspaceとVaultの`CLAUDE.md`、secretaryの`SKILL.md`に定められた
  最新の承認ルールに従う。
- ユーザーの依頼自体が特定の記録操作を明示している場合でも、規約上の承認が
  別途必要なら、実行直前に内容を提示して承認を得る。
- 規約から承認要否を判断できない場合は、書き込み前に確認する。

## 報告

作業後は、必要に応じて次を簡潔に報告する。

- 実行した操作
- 作成・更新したファイル
- 関連付けたWikiページやタスク
- 匿名化・二重管理・出典に関する注意点
- 未解決事項と次アクション

実行していない操作や、保存できなかった内容を完了済みとして報告しない。
