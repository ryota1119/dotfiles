# 機械的修正レシピ

bundle 化してよいのは、`lint --json` の入力から修正内容が一意に決まる次のレシピだけとする。
`rule` と `message` の両方が発火条件に一致しない finding は bundle に入れず、提案として扱う。

## R2-a — 日付形式の正規化

- **発火条件:** `rule` が `2` で、`message` が
  ``<key> の日付形式が不正です: <value>`` または
  ``<key> を日付として解釈できません: <value>``。`<key>` は `created` / `updated` のいずれか。
- **修正内容:** 元の値が表す日付を ISO 8601 の `YYYY-MM-DD` に正規化する。
- **修正が入力から一意に決まる根拠:** 元の値を年・月・日にただ1通り解釈できる場合は、
  対応する ISO 8601 表記もただ1つに決まる。
- **一意に決まらない場合:** 日・月の順序や年などが曖昧なら bundle から外し、元の値と
  解釈候補を提案として提示してボスの選択を待つ。

## R3-a — type に対応するディレクトリへの移動

- **発火条件:** `rule` が `3` で、`message` が
  ``type=<type> は <dir>/ に置く必要があります``（または同じ配置不一致を示す規則3の message）。
- **修正内容:** 現在の内容を `DIR_BY_TYPE` が `<type>` に対して返すディレクトリの同じ slug に
  `mode=create` し、移動元を `mode=delete` する。
- **修正が入力から一意に決まる根拠:** 有効な `type` に対する配置先は `DIR_BY_TYPE`、ファイル名は
  元ページの slug、作成内容は移動元のバイト列から一意に決まる。
- **一意に決まらない場合:** `type` が無効、配置先に同名ページが存在する、slug を維持できない、
  または内容を変える必要がある場合は bundle から外して停止し、衝突または必要な判断を報告する。

R3-a は `create` と `delete` の2 write であり、**削除対象を1件ずつ太字で示し、復旧手段を
明記する**という規約3.2の2、および規約8節の追加承認が必要になる。R3-a は単独の bundle とし、
他のレシピと同じ bundle に混ぜない。

## R7-a — index への掲載漏れの追記

- **発火条件:** `rule` が `7` で、`message` が ``wiki/index.md に載っていません``。
- **修正内容:** `wiki/index.md` のページ `type` 対応セクションの末尾へ
  ``- [[slug]] — <frontmatter の title>`` を1行追記する。説明には `title` をそのまま使う。
- **修正が入力から一意に決まる根拠:** 追記先は `type`、リンクは slug、説明は既存の `title` から
  決まり、新しい説明文を作らない。
- **一意に決まらない場合:** `type` 対応セクションがない、`title` が空または不正、同じ slug の
  行が複数ある場合は挿入位置や文言を推測せず、bundle から外して停止・報告する。

## R7-b — index の幽霊リンク行の削除

- **発火条件:** `rule` が `7` で、`message` が
  ``wiki/index.md に載っているページが存在しません: [[<slug>]]``。
- **修正内容:** `wiki/index.md` にある該当 slug の行を、その行の改行を含めて削除する。
- **修正が入力から一意に決まる根拠:** 実在しない slug と、それを1件だけ掲載する完全な行が
  入力から特定できる。
- **一意に決まらない場合:** 同じ slug が複数行にある、1行に複数リンクがある、または行の一部を
  残す判断が必要なら bundle から外し、該当箇所を提案として提示する。

## index.md の構造とプリフライト

期待する本文構造は `# Wiki Index` の下に `## Sources` / `## Entities` / `## Concepts` の3節が
この順であり、掲載行は ``- [[slug]] — 説明`` の形である。構造が違ったら挿入位置を推測せず、
停止して報告する。

規則7の修正は `wiki/index.md` の `mode=replace` を伴う。規約6.2のプリフライト検証3は、
「追記・削除した行以外がバイト単位で不変」と読み替え、その検証結果を承認提示に書く。

## 除外レシピ

次は bundle 化しない。詳細な名指し一覧と提示区分は `SKILL.md` の「修正を適用する場合」を正とする。

| 規則・finding | 除外理由 |
| --- | --- |
| 規則1の必須キー欠落、空の `title`、不正な `status` / `type` | 補う値が一意に決まらない |
| 規則1の未定義キー・type 別に使えないキー | 削除は一意でも情報を失う |
| 規則2の `updated < created` | どちらの日付を直すか一意に決まらない |
| 規則6の空セクション | 見出しを消すか本文を書くか一意に決まらない |
| 規則11の末尾改行欠落 | 改行追加では切断内容を復元できず、破損を検出できなくする |
| 規則4・5・8・9・10のすべて | D-S2 の対象外 |
